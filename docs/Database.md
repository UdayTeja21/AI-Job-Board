# Database Documentation

The AI Job Board relies on **MongoDB** (specifically MongoDB Atlas for production) as its data layer. Data modeling is handled by **Mongoose**, providing strict schema validation, type checking, and relationship enforcement.

Below is the documentation for every major collection in the database.

---

## 1. User Collection (`users`)

**Purpose**: Stores authentication credentials, profile data, and role definitions for all users (Seekers, Recruiters, and Admins).

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | String | Yes | Full name of the user. |
| `email` | String | Yes | Unique email address. |
| `password` | String | Yes | Bcrypt-hashed password. |
| `role` | String | Yes | Enum: `['seeker', 'recruiter', 'admin']`. Defaults to `seeker`. |
| `avatar` | String | No | URL to user's profile picture. |
| `skills` | [String] | No | Array of skills (primarily for seekers). |
| `bio` | String | No | Short biography. |
| `resumeUrl` | String | No | Default resume for quick applications. |

**Indexes**:
- `email` (Unique, ascending)

**Relationships**:
- A User (`role: 'recruiter'`) has a one-to-one relationship with a `Company`.
- A User (`role: 'seeker'`) has a one-to-many relationship with `Application`.

---

## 2. Company Collection (`companies`)

**Purpose**: Stores the public-facing profiles of recruiting organizations.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | String | Yes | Official company name. |
| `description` | String | Yes | Detailed description of the company culture and mission. |
| `website` | String | No | URL to company's homepage. |
| `location` | String | Yes | Headquarters location. |
| `companySize` | String | Yes | Enum range (e.g., "11-50 employees"). |
| `logo` | String | No | URL to local upload or external CDN. |
| `recruiter` | ObjectId | Yes | Reference to the `User` who created/owns this profile. |

**Relationships**:
- `recruiter` references the `User` model. 
- A Company has a one-to-many relationship with `Job` (implied via the recruiter's ID).

---

## 3. Job Collection (`jobs`)

**Purpose**: Stores all job postings created by recruiters.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | String | Yes | Job title (e.g., "Senior React Developer"). |
| `company` | String | Yes | Denormalized company name (or ObjectId ref). |
| `location` | String | Yes | Job location or "Remote". |
| `jobType` | String | Yes | Enum: `['Full-time', 'Part-time', 'Contract', 'Internship']`. |
| `salary` | String | No | Salary range. |
| `description` | String | Yes | Full HTML/Markdown job description. |
| `requirements` | [String] | Yes | Array of required skills/qualifications. |
| `aiSummary` | String | No | AI-generated marketing hook. |
| `recruiter` | ObjectId | Yes | Reference to the `User` who posted this job. |

**Indexes**:
- `recruiter` (Ascending) for fast lookup of a recruiter's jobs.
- Text index on `title`, `company`, and `description` to support search functionality.

**Relationships**:
- `recruiter` references the `User` model.
- One-to-many relationship with `Application`.

---

## 4. Application Collection (`applications`)

**Purpose**: Represents a candidate's submission to a specific job posting. It tracks the ATS status and stores AI evaluation data.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `job` | ObjectId | Yes | Reference to the `Job` applied for. |
| `seeker` | ObjectId | Yes | Reference to the `User` who applied. |
| `resume` | String | Yes | URL to the uploaded resume file. |
| `coverLetter` | String | No | Optional cover letter text. |
| `status` | String | Yes | Enum: `['Applied', 'Reviewing', 'Interview', 'Offered', 'Hired', 'Rejected']`. |
| `aiMatchScore` | Number | No | AI-generated match percentage (0-100). |
| `aiAnalysis` | String | No | Qualitative AI feedback. |
| `aiMatchedSkills`| [String] | No | Array of matched skills generated by AI. |
| `aiMissingSkills`| [String] | No | Array of missing skills generated by AI. |

**Indexes**:
- Compound Unique Index on `{ job: 1, seeker: 1 }` to prevent duplicate applications to the same job.

**Relationships**:
- `job` references the `Job` model.
- `seeker` references the `User` model.

---

## 5. Notification Collection (`notifications`)

**Purpose**: Stores system alerts for users (e.g., application status changes).

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `recipient` | ObjectId | Yes | Reference to the `User` receiving the alert. |
| `type` | String | Yes | Enum: `['StatusUpdate', 'NewJobMatch', 'SystemMessage']`. |
| `message` | String | Yes | The notification content. |
| `isRead` | Boolean| Yes | Defaults to `false`. |
| `link` | String | No | Optional URL to redirect upon clicking. |

**Relationships**:
- `recipient` references the `User` model.
